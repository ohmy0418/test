너는 개발자가 작업을 안전하게 마무리하도록 돕는 개발 어시스턴트야.
대상 이슈: $ARGUMENTS

**중요 원칙: 사용자가 명시적으로 승인하기 전에는 Jira 상태를 바꾸지 마.** 점검 결과를 먼저 보여주고 승인을 받는다.

> 키 처리·스냅샷 경로·브랜치명 규칙은 `jira-start.md`와 동일하게 유지해야 한다. 한쪽 규칙을 바꾸면 다른 쪽도 함께 바꿔야 한다.

## 1단계: 입력값 검증  (jira-start와 동일하게 처리)
- `$ARGUMENTS`가 비어 있으면 중단하고, 이슈 키를 입력하라고 안내해줘.
- 공백으로 여러 값이 들어오면 어느 것이 이슈 키인지 모호하므로, 임의로 추측하지 말고 중단해서 사용자에게 확인해줘.
- 앞뒤 공백만 제거하고, 값 자체는 사용자가 입력한 그대로 사용한다.

## 2단계: 이슈-브랜치 정합성 확인
- 현재 git 브랜치명을 확인해줘. 브랜치명이 대상 키와 다르면 다른 이슈를 실수로 완료 처리하는 상황일 수 있으니, 알리고 계속할지 확인해줘 (임의로 브랜치를 전환하지 마).
- 이미 main에 머지된 뒤라면 브랜치가 불일치하는 것이 정상이다. 이 경우 `git log --oneline --grep="\[<KEY>\]"`로 해당 이슈의 커밋이 실제로 기본 브랜치에 들어갔는지 확인해 판단 근거로 삼는다.

## 3단계: 구현 상태 수집
- `git log --oneline --grep="\[<KEY>\]"`로 이 이슈의 커밋 목록을 찾는다.
- 커밋이 하나도 없으면 **중단하고 사용자에게 알린다.** 구현 흔적이 없는 이슈를 완료 처리하지 않는다.
- `git status`로 커밋되지 않은 변경이 남아 있는지 확인한다. 남아 있으면 완료 처리 전에 알린다 (임의로 커밋하지 않는다).
- `gh pr list --search "<KEY>" --state all` 등으로 관련 PR과 머지 여부를 확인한다. `gh`를 쓸 수 없으면 이 항목은 "확인 불가"로 표시하고 넘어간다.

## 4단계: 요구사항 대비 점검
- `.claude/jira-snapshots/<KEY>.json`(없으면 `.md`)에서 Acceptance Criteria를 읽는다.
- 관련 소스 파일을 확인해 **AC 항목별로 구현되었는지 표로 정리**한다. 판단 근거(파일:라인)를 함께 적는다.
- 근거를 찾지 못한 AC는 "충족"으로 적지 말고 `확인 필요`로 표시한다. 여기서 코드를 고치지 않는다.

## 5단계: 스냅샷 최신성 확인
- Jira MCP로 현재 이슈의 `updated` 시각을 조회해 스냅샷의 `updated`와 비교한다.
- 다르면 완료 처리 전에 알린다: "구현 이후 Jira 요구사항이 변경되었을 수 있다. `/jira-sync <KEY>`로 먼저 확인할 것을 권장한다."
- 사용자가 그래도 완료 처리를 원하면 진행한다. 이 확인은 차단이 아니라 경고다.

## 6단계: 승인 요청
아래 형식으로 정리해 보여주고 완료 처리 승인을 기다린다.

1. **이슈**: 키 / 제목 / 현재 상태
2. **구현 근거**: 커밋 목록, PR 번호·머지 여부, 미커밋 변경 유무
3. **AC 점검**: 항목별 충족 / 확인 필요 (근거 포함)
4. **스냅샷 최신성**: 일치 / 구현 이후 Jira 변경 있음
5. **완료 처리 시 수행할 작업**: 상태 전이(→ 완료), 남길 코멘트 내용
6. **확인 필요 사항**

## 7단계: 완료 처리  (승인 후)
- `jira-status-updater` 서브에이전트에 다음을 전달해 위임한다. 이 커맨드에서 `transitionJiraIssue`를 직접 호출하지 않는다.
  - 대상 이슈 키
  - 목표 상태: `완료`
  - 코멘트로 남길 링크: 브랜치명, 커밋 해시·제목, PR URL (확인된 것만)
- 전이 후보가 모호하거나 필수 필드가 요구되면 서브에이전트가 사용자에게 확인을 요청한다. 대신 값을 채워 넘기지 마.
- 전이 실패는 그대로 사용자에게 보고한다. 다른 전이로 우회하지 않는다.

## 출력 형식 (완료 후)
- **상태 변화**: `<이전>` → `<현재>` (또는 건너뜀/실패 사유)
- **코멘트**: 추가함 / 해당 없음
- **남은 확인 사항**: 4단계에서 `확인 필요`로 남은 AC 항목이 있으면 여기에 다시 표시
